# =============================================================================
# THE CANONICAL FORM IS THE GLYPH FORM
#
# The form a spec IS, is the glyph form. A word is how you TYPE a glyph in, not
# a different form of the spec: the compiler canonicalises every word to its
# glyph, so a word spec and a glyph spec are the same spec.
#
# Words are accepted on input, and the checks run on the compiled glyph side.
# That is what makes typing words safe: a word with no concept behind it
# becomes a glyph that is not in the base, and GLYPH_KNOWN dies on it. An
# invention has nowhere to go, so it cannot be hidden.
#
# The reason for the rule is not that words are bad. It is that a word can be
# invented, and an invented word is indistinguishable from a real one, so the
# hole was invisible. Five names got in:
#
#     minimayz   maksimayz   menu   bar   chrome
#
# Two of them spell concepts the base already had - minim is ⇲ and maxim is ⇱
# - so those were misspellings, and the word layer let them stand. Three have
# no glyph at all, and those are holes in the base, not misspellings.
#
# Nobody has to type a glyph to work in this language. Typing is a limit of the
# keyboard, not of the language, and it is not a reason to move the canonical
# form. Type the words; the compiler hands back the glyphs; the checks read the
# glyphs.
#
# ANCHOR - the anchor glyph is •. Its textual spelling is &-> and the compiler
# emits • in its place. It is forced: it opens every abstract.
# • is the one glyph that is overloaded - it is the constructor &-> AND the
# concept • - so the position decides. At the head of a line it is the
# constructor &->, anywhere else it is the concept •. Do not split them;
# there are not enough free glyphs to give the constructor its own, and hunting
# for spares across 50-60 abstract lines is how the work gets abandoned.
#
# =============================================================================
# TWO KINDS OF id - and the frame is what tells them apart
#
#   id INSIDE a spec      glyphs, framed:  ▹⎾⏀⏆◂
#   id OF a proto/blueprint   a readable name:  win.chrome, py.ide.frame
#
# NEVER name a prototype or a blueprint with glyphs. Not once, not as a
# shorthand, not "just this one".
#
# The reason is use(). A prototype and a blueprint exist to be pulled in:
#
#     é(win.chrome)
#
# and that call comes from another spec, from a tool, from a document, and from
# a person typing a message. ▹⎾⏀⏆◂ cannot be said out loud, cannot be
# remembered between sessions, and the renderer has no word for it, so the
# human report of a spec would show a glyph where a handle belongs. A name is
# an interface to something; glyphs are not.
#
# A spec-local id has none of those duties. It never leaves its spec, so it can
# be a generated sequence, and generating it means nobody has to invent a word
# and nobody can invent one by accident. That was the point of the frame:
#
#     ▹bar◂        a free word, declared local, not a base concept
#     ▹⎾⏀⏆◂        a generated id, unnameable and unrememberable on purpose
#     bar          illegal - looks exactly like a concept, which is how
#                  minimayz, maksimayz, menu, bar and chrome entered a spec
#                  that then passed every check
#
# A bare name is a typo with no claim. Framed, it is a declaration.
#
# ALPHABET AND FRAME - fixed, contiguous, never extended:
#
#     frame    ▹ U+25B9  open, points INWARD      ◂ U+25C2  close, filled
#     alphabet ⎾⎿⏀⏁⏂⏃⏄⏅⏆⏇⏈⏉⏊⏋⏌⏍  U+23BE..U+23CD, sixteen
#     length   exactly 4
#     order    significant: 16^4 = 2^16 = 65536
#
# Contiguous is the whole reason it is safe. An id is recognisable by shape, and
# the dictionary can never take this run, because the run is defined as
# "everything in this range". Sixteen glyphs out of 322; the rest stays free.
# The frame points inward, like a bracket rather than a guillemet, so the record
# inside reads as bracketed content.
# =============================================================================
#
# This file is ENGLISH. It describes the language, it is not written in it.
# The description after the dash is English. The examples are GLYPHS - a
# language that teaches its syntax in words teaches the wrong form, and the
# wrong form is what gets written.
# =============================================================================

# --- APPENDED, not in alphabetical order ---------------------------------
# The frame. U+25B9 opens and points INWARD, U+25C2 closes and points
# inward too, and is filled where the opener is hollow so the two differ by
# fill as well as by direction in one colour. A bracket points inward, a
# guillemet points outward, and inward reads as a bracket.
#
# It replaced the symmetric quotes because quotes PROTECT their content from
# the compiler, so a payload written in them never came back and no round trip
# could ever close. The frame does not protect, so the spine and the payload
# behave the same and the circle becomes a fixed point.
#
# For a reader of the report these two are visually byte code. That is the
# price of the two-ends split, and it is paid where it costs least: the report
# may render the frame as quotes, the glyph form keeps the glyph.
*-> idopen       - open of the frame, points inward like a bracket. an id is written
     between idopen and idshut. outside the frame an alphabet glyph is not an id,
     it is a typo with no claim. U+25B9
*-> idshut       - close of the frame, filled where idopen is hollow, so the pair
     differs by fill as well as by direction in one colour. U+25C2
